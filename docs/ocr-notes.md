# Заметки по распознаванию ценников

Этот файл — живая спецификация для парсера. Каждый новый формат = новый тест + новая запись здесь.

## Что должен находить парсер

1. **Цену** — итоговую стоимость упаковки.
2. **Количество** — вес или объём упаковки; диапазон (`230-240 г`) сохраняется как подпись,
   для расчёта берётся верхняя граница.
3. **Единицу** — граммы/килограммы или миллилитры/литры.
4. **Название** — опционально, best-effort; знаки кавычек и `ж/б` сохраняются как на ценнике.

## Два OCR-слоя

- Tesseract (`rus`) читает кириллицу, вес и **мелкие копейки**; крупные рубли теряет.
- RapidOCR читает **крупные рубли**; кириллицу и копейки (`99` → `66`) читает ненадёжно.
- `OcrTokenMerger` сначала собирает кандидатов-ценники: уверенные крупные цифры RapidOCR высотой
  не менее 50% от максимальной. Затем выбирает якорь — ближайшего к центру кадра среди кандидатов
  высотой не менее 60% от максимальной.
- Копейки берутся из Tesseract (при отсутствии — из RapidOCR) в вертикальной полосе якоря;
  слова и вес — из Tesseract над ценой. Каждый токен привязывается к ближайшему якорю, поэтому
  боковые ценники и текст на упаковке в сводку не попадают.
- Каждый токен относится к ближайшему ценнику-якорю; токены соседних ценников в сводку не попадают.
- Даты, штрихкоды, коды и служебные надписи отбрасываются.
- Если якорь не найден, сводка строится по порядку строк без геометрической привязки; надёжной цены в этом случае нет.
- Если локальная модель Tesseract не загрузилась, распознавание завершается отдельной ошибкой, а не неполной ценой по RapidOCR.

## Типичные написания (синтетические примеры)

```
ТВОРОГ 5% 350 г                 240,00 ₽
Творог 320 г                   212 р
Молоко 1 л                     129,90
Сок 0,95 л                     149 ₽
Йогурт 130г                    89,50 руб.
Цена за 1 кг: 685,71 ₽
2,49 кг                        399,00 ₽
Объём 950 мл                   119,00 ₽
```

## Правила парсинга

- Запятая и точка — оба допустимые разделители дробной части. Нормализовать к `.`.
- Пробелы между числом и единицей необязательны: `350г`, `350 г`, `0,95л`.
- `кг → 1000 г`, `л → 1000 мл`; `мг` игнорировать как шум.
- Если есть явная строка «цена за 1 кг/1 л», использовать её как приоритетную, но сохранить флаг источника.
  Фраза «цена за 1 кг/л» не считается ни количеством упаковки, ни ценой упаковки.
  Формат без `1` («цена за кг») не поддерживается.
- Цена без количества (например, только `240 ₽`) → `Unparseable`, не угадывать.
- Несколько чисел в строке: сначала искать цену рядом с валютным знаком, затем количество рядом с единицами.
- Шум (штрихкоды, служебные надписи, «Акция», даты) отбрасывать.
- Регистр не важен.

## Тестовые кейсы (обязательные)

- `350 г / 240 ₽` → 685,71 ₽/кг; `320 г / 212 ₽` → 662,50 ₽/кг.
- `1 л / 129,90 ₽` → 129,90 ₽/л; `950 мл / 119 ₽` → 125,26 ₽/л.
- Повреждённый/пустой текст → `EmptyText` / `Unparseable`, без падения.
- Два ценника в кадре → берём ближайший к центру.
- Все тринадцать реальных кейсов из таблицы выше — на уровне `OcrTokenMerger` + `PriceTagParser`;
  те же эталоны проверяются сквозным тестом на настоящих JPEG (устройство/эмулятор).
- Device-тест сверяет числовые поля точно, а название и подпись веса — после нормализации
  регистра, кавычек, тире и пробелов: вывод OCR зависит от ABI/рантайма. Точные строки остаются
  в JVM-тесте на сырых токенах.
