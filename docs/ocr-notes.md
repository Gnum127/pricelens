# Заметки по распознаванию ценников

Этот файл — живая спецификация для парсера. Здесь фиксируем реальные форматы, попадающиеся
на ценниках, и правила их разбора. Каждый новый формат = новый тест + новая запись здесь.

## Что должен находить парсер

1. **Цену** — итоговую стоимость упаковки.
2. **Количество** — вес или объём упаковки.
3. **Единицу** — граммы/килограммы или миллилитры/литры.
4. **Название** — опционально, best-effort.

## Типичные написания (example)

```
ТВОРОГ 5% 350 г                 240,00 ₽
Творог 320 г                   212 р
Молоко 1 л                     129,90
Сок 0,95 л                     149 ₽
Йогурт 130г                    89,50 руб.
Цена за 1 кг: 685,71 ₽
2,49 кг                        399,00 ₽
Объём 950 мл                   119,00 ₽
```

## Правила

- Запятая и точка — оба допустимые разделители дробной части. Нормализовать к `.`.
- Пробелы между числом и единицей необязательны: `350г`, `350 г`, `0,95л`.
- `кг → 1000 г`, `л → 1000 мл`; `мг` игнорировать как шум (или отдельный случай).
- Если есть явная строка «цена за 1 кг/1 л», использовать её как приоритетную, но сохранить флаг источника.
  Фраза «цена за 1 кг/л» не считается ни количеством упаковки, ни ценой упаковки.
  Формат без `1` («цена за кг») не поддерживается.
- Цена без amounts (например, только `240 ₽`) → `Unparseable`, не угадывать.
- Несколько чисел в строке: сначала искать цену рядом с валютным знаком (`₽`, `р`, `руб`),
  затем количества рядом с единицами (`г`, `кг`, `мл`, `л`).
- Шум (штрихкоды, служебные надписи, «Акция», даты) отбрасывать.
- Регистр не важен.

## Тестовые кейсы (обязательные)

- `350 г / 240 ₽` → 685,71 ₽/кг.
- `320 г / 212 ₽` → 662,50 ₽/кг → выгоднее, чем первый.
- `1 л / 129,90 ₽` → 129,90 ₽/л.
- `950 мл / 119 ₽` → 125,26 ₽/л.
- Повреждённый/пустой текст → `EmptyText` / `Unparseable`, без падения.
- Два ценника в кадре → пока берём первый уверенно распознанный (в прототипе);
  в будущем — выбор пользователем.

## Ограничения ML Kit на ценниках

- Мелкий шрифт и блики — основная проблема; в UI нужна подсказка «держите ровно, избегайте бликов»
  и рамка наведения.
- ML Kit может пере путать `8` и `3`, `0` и `О` — поэтому парсер должен быть устойчив
  к опечаткам и отдавать `sourceText` для ручной проверки пользователем.
- Если распозналось несколько строк, склеивать их с переводом строки и запускать парсер по целому блоку.
